## Current Application Summary

CoolStore is a retail e-commerce sample monolith originally built as a Java EE 7 application
deployed on JBoss EAP 7.4 (standalone-full-ha clustering) with ActiveMQ JMS messaging,
JPA/Hibernate persistence against PostgreSQL, and Keycloak v20.0.5 for authentication. The
business domain covers a product catalog, shopping cart with promotion/shipping calculation,
and order checkout. An AngularJS 1.x single-page frontend (served from `src/main/webapp`)
talks to JAX-RS REST endpoints; checkout publishes an order message to a JMS topic consumed
by two MDBs (order persistence and inventory notification).

A first migration pass (documented in `migration/MIGRATION-COMPLETE.md`) has already
translated all 28 main-source Java files from Java EE 7 constructs to Quarkus 3.8.1
(`javax.*` → `jakarta.*`, EJB → CDI, JMS MDBs → SmallRye Reactive Messaging over Kafka,
`persistence.xml`/`web.xml` → `application.properties`, Flyway for schema management).
The application compiles, but the migration is **not complete**: security is stubbed,
production datasource is unconfigured, the audit-logging integration was removed (stubbed),
tests still contain legacy imports, and the app has never been containerized or deployed
to a modern platform. This migration plan covers the remaining work to finish, harden,
containerize, and deploy the Quarkus application.

## Migration Approach

**Strategy:** Phased migration (incremental completion of the in-flight migration),
ordered by the rgctl migration plan and risk.

**Reasoning:**
- The code translation is largely done; remaining work is configuration, integration,
  testing, and deployment — each independently verifiable
- Phasing lets each slice (tests → audit logging → security → data → container →
  OpenShift) be validated before the next, with rollback points
- The app is small (28 main files), so per-package phases are short; but messaging and
  security changes are behavior-sensitive and need parity validation

**Phases (see mig-plan-workspace/tasks.md for the full dependency-ordered breakdown):**
1. Baseline & verification — reproduce build, fix remaining test-source legacy imports,
   run the existing test suite to establish current behavior
2. Java 21 + audit-logging-library 2.x integration (rules/rule.yaml rules
   audit-logging-0001…0005)
3. Security hardening — Quarkus OIDC/Keycloak wiring, endpoint authorization,
   CORS, secret externalization
4. Production data & messaging configuration — PostgreSQL + Flyway + Kafka profiles,
   remove H2-in-prod
5. Containerization — multi-stage Containerfile, health probes, non-root runtime
6. OpenShift deployment — manifests, ConfigMaps/Secrets, CI/CD, smoke tests
7. Behavior parity validation — characterization/E2E tests against key journeys

**Key Considerations:**
- Transactional semantics: `@Incoming` Kafka consumers must keep `@Transactional`
  (SmallRye does not auto-wrap; regression here causes `TransactionRequiredException`)
- Pub/sub semantics: two consumer groups on the same `orders` topic preserve the old
  JMS topic broadcast behavior — do not load-balance them into one group
- The `weblogic.application` shim and `src/main/webapp/bower_components/` vendored JS
  are non-functional legacy mass: exclude from container image / consider removing
- REST API paths must remain compatible with the AngularJS frontend (`app/services/*.js`)
- 10 TODO(port)/BUG(port) markers remain in main source (ShoppingCartService null-safety
  BUG(port) items, RestApplication base-path TODOs, audit stub in OrderService)
