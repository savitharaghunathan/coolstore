## Current Application Summary

CoolStore is a retail storefront monolith originally built as a Java EE 7 application
for JBoss EAP 7.4: an AngularJS 1.x / PatternFly single-page frontend served from a WAR,
JAX-RS REST endpoints (cart, product, order), stateless/stateful EJB services (catalog,
pricing/promotions, shipping, shopping cart), JPA/Hibernate persistence against
PostgreSQL, JMS order processing over an ActiveMQ topic, and Keycloak-based
authentication. rgctl indexed 1,263 files into 36,511 nodes and 127,928 edges; the
graph is dominated by the frontend's bower dependencies (jQuery, PatternFly, d3,
DataTables), with the Java backend resolving into four clean subsystem communities:
`com.redhat.coolstore.model`, `com.redhat.coolstore.service`, `com.redhat.coolstore.rest`,
and `com.redhat.coolstore.utils`, plus a `weblogic.application` compatibility shim layer.

The codebase is **mid-migration**. A prior six-step kit-driven run already translated the
main Java source from Java EE 7 to Quarkus 3.8.1: all 26 main classes now use `jakarta.*`
imports (zero `javax.*` remain in main), EJBs became CDI beans (`@ApplicationScoped`),
ActiveMQ `@MessageDriven` beans became SmallRye Reactive Messaging `@Incoming`/`@Channel`
consumers/producers backed by Kafka, and `application.properties` (dev/test/prod profiles)
plus Flyway migrations (`V1_1__CreateSchema.sql`, `V1_2__AddInitialData.sql`) are in place.
Compilation was verified (47 → 0 errors) in the prior run. What remains is production
readiness and deployment: one test file still imports `javax.jms`, the Keycloak/OIDC
security port is unconfigured, the production PostgreSQL datasource is not provisioned
(H2 in dev/test), legacy artifacts survive (`WEB-INF/web.xml`, `WEB-INF/beans.xml`,
`src/main/java/weblogic/application/*` shims, `index.jsp`/`health.jsp`), the AngularJS
frontend is not yet served from Quarkus static resources, and there is no container
image or OpenShift deployment.

**Technology Stack (current state):**
- Java 11 (`maven.compiler.release=11`), Maven build, `quarkus-bom` 3.8.1, jar packaging
  (`com.redhat.coolstore:coolstore-quarkus:1.0.0-SNAPSHOT`)

  jdbc-postgresql, jaxb, smallrye-reactive-messaging-kafka, narayana-jta, flyway,

- Data: PostgreSQL (production target), H2 in-memory (dev/test), Flyway schema management
- Messaging: Apache Kafka via SmallRye Reactive Messaging — `orders` topic with two
  consumer groups (`coolstore-orders`, `coolstore-inventory`) preserving the original

- Security: Keycloak (realm export `realm-export.json` in repo); OIDC port pending

**Architecture:**
- Monolithic 3-tier: AngularJS UI → JAX-RS/RESTEasy Reactive REST layer

- Integration points: PostgreSQL, Kafka, Keycloak (OIDC), static web frontend

## Migration Approach

**Strategy:** Phased completion (hybrid) — the code-level translation from Java EE 7 to
Quarkus is substantially done; the remaining migration proceeds as incremental,
independently verifiable phases rather than a big-bang cutover.

**Reasoning:**
- The highest-risk translation (namespace, EJB→CDI, JMS→SmallRye/Kafka) is complete and
  compiles; residual risk concentrates in runtime behavior parity (messaging semantics,
  transactions, security), configuration, and deployment — each best verified behind its
  own gate
- The app is small (~3.9K LOC Java) but the async order flow is business-critical:
  a phased approach lets each phase be validated (build, test, smoke) before the next
  begins, with rollback to the previous phase at every gate
- rgctl's exported migration plan orders the Java packages
  `com.redhat.coolstore.model` → `com.redhat.coolstore.utils` →
  `weblogic.application` (compat shims, to be removed) → `com.redhat.coolstore.rest` →
  `com.redhat.coolstore.service`, matching the natural dependency order for any
  remaining code surgery and test restoration

**Phases (indicative):**
1. Baseline & verification — re-establish a green build/test baseline; fix remaining
   `javax.jms` test imports; add missing test dependencies (`mockito-junit-jupiter`)
2. Code & artifact cleanup — delete `WEB-INF/web.xml`, `WEB-INF/beans.xml`,
   `weblogic/application/*` shims, JSPs; move frontend to Quarkus static resources
3. Security port — Keycloak OIDC configuration, endpoint annotations, CORS
4. Data & config hardening — production PostgreSQL datasource, Flyway validation,
   profile separation
5. Test restoration & characterization — port/restore the 23-test suite as the parity
   baseline; messaging tests with in-memory Kafka connector; E2E checkout flow
6. Containerization — multi-stage Containerfile, non-root runtime image
7. OpenShift deployment — manifests, probes, secrets, routes, Kafka/Keycloak/PostgreSQL
   wiring
8. Validation & parity — smoke + performance checks, monitoring, sign-off and
   decommissioning of legacy deployment path

**Key Considerations:**
- **Messaging semantics**: JMS topic broadcast → Kafka with distinct consumer groups;
  consumers need `@Transactional` (SmallRye `@Incoming` does not start transactions,
  unlike EJB MDBs); DLQ failure strategy already configured and must be verified
- **Frontend serving**: Quarkus jar does not serve JSPs — `index.jsp`/`health.jsp` must
  be replaced (static `index.html` under `META-INF/resources`; health via
  `quarkus-smallrye-health`)
- **Security gap**: `@RolesAllowed`/`@PermitAll` currently absent from endpoints; OIDC
  config is placeholder — the checkout flow must require authentication as in the
  original app
- **Secrets hygiene**: rgctl security scan flagged 7 potential secrets
  (Keycloak `realm-export.json` client secrets, datasource credentials in docs) —
  must be externalized to OpenShift Secrets before production
- **Test debt**: 1 test file on `javax.jms` imports; missing `mockito-junit-jupiter`;
  known deferred markers in code: 18 `TODO(port)`/`BUG(port)`/`PERF(port)` tags
  (audit-logging library stub, multi-cart support, null-safety in
  `initShoppingCartForPricing()`)
- **Data parity**: H2 (dev/test) vs PostgreSQL (prod) — Flyway migrations must be
  validated against PostgreSQL specifically

## Constraints and Risks

**Constraints:**
- Quarkus 3.8.1 and Java 11 are already committed in `pom.xml`; any version bumps
  (e.g., Java 17) must be justified and coordinated
- Kafka, PostgreSQL, and Keycloak must be available in the target OpenShift environment
  (AMQ Streams, database operator/managed service, Keycloak operator)
- The prior migration run left 18 deferred `TODO(port)`/`BUG(port)`/`PERF(port)` markers
  that are documented as non-blocking but must be triaged, not silently dropped
- The frontend is vendored bower-era AngularJS 1.x — out of scope for a rewrite; it must
  be served as-is from static resources
- Exact team size, skill matrix, and deadline pressure are not recorded; the plan should
  assume a small team new-ish to Quarkus/OpenShift and include enablement time

**Risks:**
- **Messaging semantics drift** (High): JMS topic pub/sub vs Kafka consumer groups;
  transaction boundaries changed (`@Incoming` needs explicit `@Transactional`) — an
  un-transacted consumer could drop or double-process orders. *Mitigation:*
  characterization tests on the order flow, DLQ verification, Kafka companion tests.
- **Security regression** (High): OIDC port incomplete; endpoints may ship unauthenticated,
  exposing cart/order mutation. *Mitigation:* complete the security phase before any
  external exposure; E2E test asserting 401/403 behavior.
- **Secrets exposure** (Medium): 7 potential secrets flagged by rgctl (Keycloak client
  secrets in `realm-export.json`, DB credentials in docs). *Mitigation:* rotate and
  externalize to OpenShift Secrets; add CI secret scanning.
- **Frontend serving break** (Medium): JSP removal changes how `index`/`health` pages
  are served; asset paths may break. *Mitigation:* static-resource smoke tests of all
  partials and API base paths.
- **Data parity** (Medium): Flyway scripts authored/validated on H2 may diverge on
  PostgreSQL. *Mitigation:* run migrations against PostgreSQL in integration tests
  (Testcontainers) before prod.
- **Test debt** (Medium): 1 test file on legacy imports; missing test dependency;
  known null-safety `BUG(port)` in cart pricing init. *Mitigation:* test restoration
  is an explicit early phase; bug markers triaged with owners.
- **Circular dependencies flagged by rgctl** (Low): 324 cycles detected, almost all in
  vendored frontend bower code — out of migration scope but noted for any future
  frontend modernization.
